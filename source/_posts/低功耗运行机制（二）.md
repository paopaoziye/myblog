# 嵌入式基础
## 低功耗运行机制
### 低功耗运行机制（二）
#### 低功耗模式
**①简介**
>**概述**：指处理器通过**停止部分时钟**、**降低供电电压**或**关闭部分电路**，使硬件进入**低能耗运行状态**，以减少系统功耗
{%list%}
嵌入式芯片常见的低功耗模式包括Low-Power Run、Sleep、Stop、Standby和Shutdown，不同芯片对这些模式的支持情况不同
{%endlist%}
>`Low-Power Run`：处理器继续执行程序，通过降低**工作频率**与**供电电压**减少运行功耗，同时保留基本计算与外设控制能力

>`Sleep`：处理器**暂停执行程序**并**停止执行指令所需的时钟**，部分外设与系统时钟继续运行，可通过**中断或事件**快速唤醒

>`Stop`：在`Sleep`的基础上停止**总线及大部分外设**的时钟，通常保留**寄存器与`SRAM`数据**，并通过**指定唤醒源**恢复运行

>`Standby`：关闭芯片**主要电源域**，仅保留**必要的唤醒与备份功能**，**运行数据**通常会被丢失，唤醒后需要**重新启动系统**

>`Shutdown`：在`Standby`的基础上进一步关闭**非必要电源域与内部电路**，仅保留**最低限度的唤醒功能**，唤醒后需要**重新启动系统**
{%right%}
低功耗模式下，芯片并非完全停止工作，部分低速时钟、定时器及唤醒检测电路仍可保持运行，以支持定时唤醒与外部事件响应
{%endright%}
{%warning%}
更深层次的低功耗模式通常能够进一步降低静态功耗，但也可能延长唤醒时间、增加状态恢复开销，并限制可用的唤醒源
{%endwarning%}
**②休眠机制**
>**概述**：指处理器通过执行**休眠指令**，配合芯片的**休眠控制寄存器**和**时钟与电源管理模块**，控制系统进入不同低功耗模式
{%list%}
处理器休眠不是简单地停止执行程序，而是一个由软件发起、硬件执行的过程，需要软件层、处理器架构层和芯片硬件层相互配合
{%endlist%}
{%right%}
软件层判断能否休眠并配置休眠控制寄存器与时钟与电源管理模块，随后执行处理器架构提供的休眠指令使硬件进入低功耗状态
{%endright%}
>
{%warning%}
休眠前需确保唤醒源有效、中断状态正确及外设操作已妥善处理，避免系统无法唤醒、意外退出休眠或数据丢失
{%endwarning%}
```c
/*
 * 函数功能：
 * 控制 STM32F407 进入 Stop 模式
 *
 * 前提条件：
 * 已配置有效的唤醒源
 * 已处理相关中断挂起标志
 * 已完成必要的外设挂起操作
 */
void Enter_Stop_Mode(void)
{
    /* 1. 使能 PWR 外设时钟 */
    RCC->APB1ENR |= RCC_APB1ENR_PWREN;

    /* 2. 选择 Stop 模式 */
    PWR->CR &= ~PWR_CR_PDDS;

    /* 3. 选择主稳压器正常工作 */
    PWR->CR &= ~PWR_CR_LPDS;

    /* 4. 配置 Cortex-M4 深度休眠 */
    SCB->SCR |= SCB_SCR_SLEEPDEEP_Msk;

    /* 5. 确保前面的内存访问完成 */
    __DSB();

    /* 6. 等待中断，进入 Stop 模式 */
    __WFI();

    /* 7. 唤醒后同步指令执行 */
    __ISB();

    /* 8. 清除深度休眠配置 */
    SCB->SCR &= ~SCB_SCR_SLEEPDEEP_Msk;

    /* 9. 恢复原有系统时钟配置 */
    /* Restore_System_Clock(); */
}
```

>Sleep 模式主要通过停止 CPU 时钟降低功耗，相关外设和其他系统时钟仍可按配置继续运行，适合频繁出现的短暂空闲阶段

>Stop 模式在停止 CPU 的同时关闭主要运行时钟，并使内部稳压器维持正常或低功耗工作状态，在降低功耗的同时保留程序运行上下文
从 Stop 唤醒后，STM32F407 使用 HSI 作为系统时钟，原有 PLL 等时钟配置不会自动全部恢复。 如果应用需要原来的工作频率，就必须完成相应的时钟恢复操作
Stop 适合需要保留 RAM 数据、但允许系统暂停主要工作一段时间的场景，例如周期性采样设备

>Standby 模式通过关闭芯片主电源域进一步降低功耗，仅保留必要的待机与备份电路
Sleep 和 Stop 唤醒后可以恢复之前的程序执行，而 Standby 唤醒后需要按照复位启动流程重新执行程序
适合长时间待机、低频率唤醒或者需要极低待机电流的设备
{%right%}

{%endright%}
{%warning%}
更深的低功耗模式通常可以降低更多静态功耗，但也可能增加唤醒时间、状态恢复成本，并限制可用的唤醒源
{%endwarning%}
Cortex-M4 主要提供两种休眠指令WFI和WFE，该指令负责让 CPU 进入等待状态，具体进入哪种模式，需要结合 Cortex-M4 的系统控制寄存器与 STM32 的电源控制寄存器

Cortex-M4 的 SCB->SCR 寄存器包含以下重要控制位，SLEEPDEEP选择普通 Sleep 或 Deep Sleep，SLEEPONEXIT	中断处理结束后直接进入休眠，SEVONPEND	控制中断挂起时的事件产生行为

SLEEPDEEP = 0	Sleep，SLEEPDEEP = 1，PDDS = 0	Stop，SLEEPDEEP = 1，PDDS = 1	Standby
PDDS 位属于 STM32 的 PWR->CR 寄存器。另外，Stop 模式还可以通过 LPDS 等控制位选择内部稳压器工作状态
Cortex-M4 负责提出休眠请求，STM32 的电源管理硬件则根据配置决定具体的低功耗状态

WFI 和 WFE 可能因为已有待处理中断或事件而不真正进入休眠。因此，操作系统或 BSP 需要妥善处理休眠前的状态检查与中断竞争
