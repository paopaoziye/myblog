# 通信协议
## UART协议
### UART协议（一）
#### 协议简介
**①引言**
>**概述**：也称为**通用异步收发器**，是一种常用的**异步全双工串行通信方式**，主要用于设备间的**点对点数据传输**，采用`LSB First`
{%list%}
典型UART至少由TX、RX和GND三根信号线组成，分别用于发送数据、接收数据和提供电平参考，通信时发送端TX连接接收端RX
{%endlist%}
>`STM32`等芯片中常见的**串行通信外设**为`USART`，不仅支持`UART`的**异步通信模式**，还支持通过`CK`输出**同步时钟**

>`USART`通常还提供`RTS`和`CTS`进行**硬件流控**，用于控制发送端**暂停或继续发送数据**，避免接收端因处理不及时而发生**数据溢出**
{%right%}
UART硬件结构简单且开发成本较低，还可配合RS-232和RS-485等物理层接口，提高传输距离和抗干扰能力
{%endright%}
>`MCU`的`UART/USART`引脚通常直接使用`MCU GPIO`的逻辑电平，具体**输入电平阈值**以数据手册中的`VIH`、`VIL`参数为准

>`UART`信号经过`RS-232`收发器会被转换为`RS-232`**电气信号**，其逻辑`0`由`+3V~+15V`表示，逻辑`1`由`-3V~-15V`表示

>`UART`信号经过`RS-485`收发器会被转化为对应的**差分信号**`A`和`B`，使用`A`、`B`两根线之间的**电压差**表示逻辑信号
{%warning%}
UART通信速率、传输距离和抗干扰能力有限，且本身缺少设备寻址、总线仲裁和多节点管理机制，不适合高速复杂网络通信
{%endwarning%}
**②帧格式**
>**概述**：典型的`UART`数据帧由**起始位**、**数据位**、**校验位**和**停止位**组成，并以设定的**波特率**传输
{%list%}
UART最常见的数据格式为8N1，即8个数据位、无校验和1个停止位，此时UART发送一个字节需要传输10 bit
{%endlist%}
>**起始位**：`UART`总线**空闲时**通常保持逻辑`1`，发送端发送一位逻辑`0`产生**起始信号**通知接收端**一帧新的数据**即将开始

>**数据位**：长度为`5-9bit`，通常采用`LSB First`，即**低位先发送**，如果启用了校验则校验位为**数据位的最后一位**

>**校验位**：用于对数据进行简单的**错误检测**，常见的方式为**无校验**、**奇校验**和**偶校验**，偶校验即**数据位和校验位**中`1`的数量为偶数

>**停止位**：固定为逻辑`1`，用于表示**当前数据帧结束**，常见长度为`1 bit`、`1.5 bit`和`2 bit`，后续**没有新的数据**总线会进入**空闲状态**
{%right%}
UART通过预设波特率确定每个bit的时间，并在检测到起始位后通过过采样在各数据位中心进行采样，实现无时钟线的异步通信
{%endright%}
{%warning%}
通信双方必须配置一致，包括波特率、数据位、校验位和停止位等，否则可能导致乱码、校验错误或帧错误
{%endwarning%}
**③发送流程**
>**概述**：`UART`的发送流程为`CPU -> TDR -> TX FIFO -> TX Shift Register -> TX Pin`，其中部分`UART`外设可能**不提供**`TX FIFO`
{%list%}
CPU将数据写入发送数据寄存器TDR，经过TX FIFO缓冲后进入TX Shift Register，最后按照设定的帧格式和波特率从TX Pin中输出
{%endlist%}
>在`UART`发送过程中，可通过`TXE`、`TXFNF`、`TC`和`TXFE`等标志位判断**发送缓冲区是否可写**以及**数据是否已经真正发送完成**

>`TXE`表示`TDR`为空，`TXFNF`表示`TX FIFO`未满，`TC`表示**整个发送过程完成**，`TXFE`表示`TX FIFO`已空
{%right%}
TX FIFO的作用是暂存多个待发送字节，减少CPU等待，提高连续发送效率，并且硬件会自动添加起始位、停止位和可选的校验位
{%endright%}
{%warning%}
真正负责逐位发送的是TX Shift Register，TXE/TXFNF仅表示可以继续写入数据，而TC才表示移位寄存器中的最后一帧发送完成
{%endwarning%}
**④接收流程**
>**概述**：`UART`的接收流程通常为`RX Pin -> RX Shift Register -> RX FIFO -> RDR -> CPU`，其中部分`UART`外设可能**不提供**`RX FIFO`
{%list%}
RX Pin接收数据后，经RX Shift Register逐位采样并还原数据，经RX FIFO缓冲后写入接收数据寄存器RDR，最后由CPU读取
{%endlist%}
>在`UART`接收过程中，可通过`RXNE`、`RXFNE`和`RXFF`等标志位判断**接收缓冲区状态**以及**数据是否已经真正接收完成**

>`RXNE`表示`RDR`中**存在待读取数据**，`RXFNE`表示`RX FIFO`非空，`RXFF`表示`RX FIFO`已满
{%right%}
RX FIFO用于暂存已接收数据，为CPU提供处理时间，从而降低连续接收过程中发生数据丢失的风险
{%endright%}
{%warning%}
若每接收一个字节就触发一次中断，会显著加重CPU负担，可以采用FIFO并设置接收阈值批量处理数据，降低中断频率与CPU开销
{%endwarning%}
**⑤错误标志**
>**概述**：`UART`在接收过程中可通过`PE`、`FE`、`NE`和`ORE`等错误标志判断是否发生**校验错误**、**帧错误**、**噪声错误**或**接收溢出**
{%list%}
错误标志用于检测并定位UART接收过程中的异常状态，便于软件及时处理并避免错误继续影响后续通信
{%endlist%}
>`PE`：表示接收数据的**奇偶校验结果**与设定规则不一致，通常由**校验配置不匹配**或**线路干扰**引起

>`FE`：表示在**预期的停止位位置**未检测到有效停止位，通常由**波特率不匹配**、**帧格式配置错误**或**信号干扰**引起

>`NE`：表示接收过程中检测到**噪声干扰**或**异常电平变化**，通常与**线路质量差**、**外部干扰**或**信号边沿异常**有关

>`ORE`：表示**旧数据尚未及时读取**时新数据再次到达，发生接收溢出，通常由`CPU`**处理不及时**或**接收速率过高**引起
{%right%}
错误标志能够帮助软件快速定位异常来源，区分参数配置、线路质量和数据处理等问题，并针对性地进行重传、丢弃或恢复处理
{%endright%}
{%warning%}
发生错误后应及时读取并清除对应状态标志，否则可能影响后续数据接收，具体清除方式以芯片参考手册为准
{%endwarning%}
**⑥串口协议帧**
>**概述**：在`UART`字节流之上，按照**约定格式**组织**数据和控制信息**的一条完整消息，`XMODEM`就是一种典型的**串口文件传输协议**
{%list%}
UART只负责逐字节传输，而XMODEM在此基础上定义了数据块格式、校验、确认、重传和结束机制，用于实现可靠的文件传输
{%endlist%}
>`XMODEM`将待传输文件划分为**多个固定大小的数据块**，经典版本的基本格式为`SOH | Block No | ~Block No | Data(128B) | CRC16`

>`SOH`：固定值为`0x01`，用于标识一个新的`XMODEM`数据块的**起始位**，接收端检测到`SOH`后会按**固定格式**继续解析后续字段

>`Block No`：长度为`1 Byte`的**块编号**，用于标识当前数据块的**传输顺序**，接收端可据此判断数据块是否发生**重复**、**丢失**或**乱序**

>`~Block No`：长度为`1 Byte`，其值为`Block No`的**按位取反值**，满足`Block No + ~Block No = 0xFF`，用于检查**块编号**是否正确

>`Data`：用于承载**实际文件内容**的数据区，发送端按固定大小**分块传输文件**，接收端再按`Block No`**重新拼接**

>`CRC16`：长度为`2 Byte`，发送端根据`Data`计算**校验值**，接收端**重新计算并比对**，用于判断数据在**传输过程**中是否发生错误
{%right%}
XMODEM不仅规定数据帧格式，还通过ACK/NAK确认、超时检测和自动重传机制，降低数据丢失或传输错误的风险
{%endright%}
{%warning%}
经典XMODEM每个数据块固定为128 Byte，若最后一个数据块不足 128 Byte，通常需要使用约定字符进行填充，使其达到固定长度
{%endwarning%}
